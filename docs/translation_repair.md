# hanguard 中文翻译修复

本次修复针对 WildGuard 原始源文本到中文的失真，属于数据修复，不是模型准确率优化实验。源文以英文为主，少数包含其他语言或代码；兼容字段 `original_english` 不代表每条源文都是英文。旧数据三集和旧实验的轻量记录现保存于 [历史归档](../archive/README.md)，已退出活动训练目录。尚未完成质量检查的试译不用于训练或评测。

修复产物已完成检查并生成：训练 62,155、验证 7,753、测试 7,778 条，另有 3,023 条隔离记录；全部 80,709 条仍在完整档案中。主数据不按长度筛除，407 条超过旧 370-token 限制的合格文本完整保留。详见[完整报告](../outputs/hanguard_translation_repair_20260928/report.md)与[当前 QA 状态](../data/three_source_translation_repaired/release_qa.json)。状态表示全量规则及结构核验、指定助手双语抽检已完成，不表示全量真人语义审校。

## 已确认的旧流程问题

实际旧译入口是已归档的 `legacy/scripts/translate_wildguard.py` 的本地 NLLB-200-3.3B，并非 README 历史描述中的机器翻译 API。该代码把输入截到 512 token，生成参数为 `max_new_tokens=256`。恢复源文后，现用 WildGuard 记录中有 549 条原始输入超过旧输入上限；这与输出达到上限的风险线索分别统计，不能相加作为错译总数。短文本也存在俚语直译、词义替换和否定范围失真，因此统一处理全部 WildGuard 记录，而非仅改动分类模型答错的样本。

## 固定范围与来源

- 以已有三集中的全部 46,187 条 WildGuard 记录为范围，不依据分类模型的预测、置信度或错误挑选修复对象。
- 通过历史随机重排行号、来源文件哈希及旧译文逐条匹配恢复原文；去除完全相同原文的重复翻译计算后是 45,615 段不同文本。
- 中文整理语料和 JailBench 没有相应的、已核实的外文翻译映射，本次不臆造原文或改写其正文。
- 不新增注入增强；保留来源已有的角色、引用和攻击包装。标签不根据译文、模型预测或本次复核自动修改。

## 修复与质量检查

正式译者使用本地 `Qwen3.5-4B` 原始权重，不加载 hanguard 分类头或 LoRA。固定完整翻译提示词，贪心生成，记录模型权重、配置、tokenizer、代码和提示词哈希。原文只作为 JSON 中的待译资料进入模型。正式处理前比较过通用模型、专用译者和初译后校对候选；小批结果用于选择这套处理流程，不作为各模型总体翻译准确率评测。

1. 读取完整来源文本，禁止输入静默截断。统一翻译为中文，只把正文交给翻译模型，不传入标签、集合名或分类预测。
2. 显式代码块、行内代码、严格识别的完整 Java 代码后缀和模型角色控制串作为原样字面量保护；恢复时逐字节检查。其他疑似裸代码改动进入复核。
3. 保存原文、旧译文、新译文、模型与提示词信息、结束原因、长度及质量标记。达到生成上限、拒答、缺失占位符等不能悄悄当作成功翻译。
4. 使用与分类标签无关的规则检查数字、年龄、否定、语义对象、列表、引号、角色和链接；这些规则给出复核线索，不把规则命中率称为翻译错误率。
5. 从每个集合按固定哈希随机抽取双语样本，另检查已知翻译问题。已知问题样例不替代随机抽检；抽检合格也不意味着所有译文均经人工确认。

固定随机抽检为每集 24 条，共 72 条，种子 `20260928`。翻译检查文件不提供有害标签、类别或分类预测。另有回归样本和规则触发样本，统计时与随机样本分开。双语复核由 Codex 助手完成，不冒称真人专家标注或人工金标；同一原文的旧译、模型新译、复核修订分别保留，普通措辞差异与实质语义改变分别记录。

复核修订必须绑定原文和模型译文的两个 SHA256，给出完整修订文本与具体依据。新文本重新检查代码、控制串和占位符，不允许借修订改变受保护内容。模型原译、原审计、新审计与修订来源均保留；有生成截断等确定流程错误的记录不能通过复核意见直接豁免。单条 `correct` 表示做了有记录的修改，不等于发现一条重大语义错误。

## 三集与隔离

保留记录原来的 `base_id`、来源行、标签和集合归属，重新计算新正文的规范化文本、文本标识与 tokenizer 长度。完整修复档案保留每条记录，包括未发布的内容。

本次主数据不按长度删除记录，构建时使用 `--max-tokens 0`；保存全文、token 数及超过旧实验 370-token 上限的标记。翻译质量筛选与训练长度配置分开：合格长文本仍留在原来的训练／验证／测试集合中，不截短、不回退到旧译文。

此前考虑过沿用 370-token 上限，现已取消该数据筛选条件，以免额外减少长文本和复杂包装。旧分类实验脚本对超出 370 token 的输入执行断言拒绝，不是静默截断；历史 SFT 入口也会拒绝超过其格式化长度上限的输入。当前训练入口已使用新数据和 4,096-token 上限，配合长度分桶与 token 预算，最长 3,202-token 样本可完整进入模型。不能直接套用旧配置。生成触顶导致译文完整性未建立的记录仍需隔离，这与“完整译文较长”是两个条件。

本次回查发现，规范化原文相同的 210 个组、427 条记录跨越原来的集合边界。此类跨集重复以及修复后产生的冲突或重复按统一规则隔离，不把测试记录移入训练集。多种隔离原因可能命中同一行，统计必须去重。

## 可复现入口

- 来源恢复：`scripts/hanguard/translation_provenance.py`
- 本地重译：`scripts/hanguard/repair_wildguard_translation.py`
- 代码字面量保护：`scripts/hanguard/translation_literal_guard.py`
- 标签无关质量检查：`scripts/hanguard/audit_translation_repair.py`
- 双语复核证据汇总：`scripts/hanguard/assemble_translation_reviews.py`
- 生产结果合并与复核修订：`scripts/hanguard/merge_translation_repair.py`
- 三集重建与基础审计：`scripts/hanguard/build_translation_repaired_dataset.py`
- 独立全量读回核验：`scripts/hanguard/audit_translation_repair_outputs.py`
- 本次过程文件：`outputs/hanguard_translation_repair_20260928/`

生产使用的生成器已按原始 SHA256 保存代码快照。全部生成完成后，当前脚本修复了 JSONL 读取对 Unicode 行分隔符的兼容问题，并把默认模型、提示词模式对齐正式调用的 `Qwen3.5-4B / faithful`；没有重写已生成文本或修改其提示词。原始批次与后续代码变更由 `generation_source_snapshot.json` 分别记录。严格的代码哈希检查仍会拒绝直接跨协议续写；复现历史批次须在独立检出中恢复快照到原脚本路径，并使用记录的依赖和调用参数。

新数据与旧中文评测文本不同，隔离规则也改变了有效评测样本。旧分数不能直接与新分数相减后宣称算法提升；后续对照模型必须在同一份修复后的固定数据上重新训练和评测。既有测试集已用于探索，译文修复不能使它重新成为从未查看的盲测集。

历史分类实验脚本包含旧数据路径、旧样本数断言及旧特征缓存／LoRA 初始化，现已归档。后续训练统一通过 `scripts/hanguard/train.py` 指定正式发布并在新目录登记初始化与对照协议，见[训练说明](training.md)。已完成的修复数据实验保留原始协议、模型与报告；本次仓库整理不重新训练。
